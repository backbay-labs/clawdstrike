# Input Injection Capability Guard

Computer Use Agents inject inputs (keyboard strokes, mouse clicks, touch events) into
remote sessions. Without controls, an agent could type arbitrary commands, click on any
UI element, or use touch gestures to navigate to malicious content.

## The Threat

Input injection is the mechanism through which CUA agents interact with remote desktops.
The risks include:

- **Keyboard** -- Typing arbitrary commands into terminals, password fields, or code editors
- **Mouse** -- Clicking on any UI element: download buttons, security dialogs, admin panels
- **Touch** -- Touch gestures that navigate to malicious content or approve actions
- **Unknown types** -- New input mechanisms (gamepad, voice, eye tracking) that could be
  exploited before the guard knows about them

The key insight: the guard fails closed on a **missing** field rather than a dangerous
value. If an `input.inject` action does not declare its `input_type`, it is denied
immediately -- no exceptions.

## How It Works

The guard validates `input.inject` actions through a strict validation chain:

1. **Missing field = DENY** -- The action MUST have an `input_type` field. Missing
   `input_type` is an automatic DENY (fail-closed).
2. **Allowlist check** -- The `input_type` must be in the allowed set (default: keyboard,
   mouse, touch).
3. **Postcondition probe** -- Optionally, a `postcondition_probe_hash` can be required to
   verify the result of the input injection.

This is the only guard that fails closed on a MISSING field rather than a dangerous value.
Every other guard fails on what you send -- this one fails on what you forget to send.

## Configuration

```yaml
guards:
  input_injection_capability:
    enabled: true
    allowed_input_types:
      - keyboard
      - mouse
      - touch
    require_postcondition_probe: false
```

- **`allowed_input_types`** -- List of allowed input types (default: keyboard, mouse, touch)
- **`require_postcondition_probe`** -- Require a postcondition probe hash for verification (default: false)
