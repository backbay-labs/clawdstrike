# MCP Tool Guard

## The Threat

The Model Context Protocol (MCP) gives AI agents access to external tools. Without restrictions, an agent could invoke `shell_exec` (arbitrary command execution), `raw_file_write` (bypass file guards), or `raw_file_delete` (destructive deletion).

The McpToolGuard controls which tools are allowed, which require confirmation, and which are outright blocked -- providing a capability boundary around tool invocation.

## How It Works

Decision cascade with clear precedence:

1. **Block set** checked first (always wins -- hard deny)
2. **Confirmation set** checked next (returns `RequireConfirmation` -- a warn, not deny)
3. If **allowlist is non-empty**, tool must be in allowlist to pass
4. If **allowlist is empty**, fall back to default action

The guard also enforces a `max_args_size` limit (default 1MB) using a zero-allocation counting writer, preventing agents from sending oversized payloads through tool arguments.

## Configuration

```yaml
guards:
  mcp_tool:
    enabled: true
    blocked_tools:
      - shell_exec
      - run_command
      - raw_file_write
    require_confirmation:
      - file_write
      - file_delete
      - git_push
    allowed_tools: []  # Empty = allow all not blocked
    max_args_size: 1048576  # 1MB
```
