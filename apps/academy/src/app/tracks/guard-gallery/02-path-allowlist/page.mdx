# Path Allowlist Guard

## The Threat

The inverse of ForbiddenPath. Instead of blocking known-bad paths, the PathAllowlistGuard blocks **everything** except explicitly allowed paths. This is the "deny by default" approach -- if a path isn't on the allowlist, it's denied.

This is the strictest filesystem guard: rather than trying to enumerate every dangerous path, you enumerate only the safe ones.

## How It Works

The guard maintains separate allowlists for `file_access` (reads), `file_write`, and `patch` operations. When checking an action, it dispatches to the appropriate allowlist based on action type.

Fallback chain:
- If no `file_write_allow` is configured, it falls back to `file_access_allow`
- If no `patch_allow` is configured, it falls back to `file_write_allow`

For symlink-aware matching, when the resolved path differs from the lexical path, **only** the resolved path is checked -- this prevents allowlist escapes via symlinks.

## Configuration

```yaml
guards:
  path_allowlist:
    enabled: true
    file_access_allow:
      - "**/repo/src/**"
      - "**/repo/docs/**"
    file_write_allow:
      - "**/repo/src/**"
    patch_allow: []  # Falls back to file_write_allow
```
