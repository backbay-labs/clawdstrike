# Patch Integrity Guard

## The Threat

When an agent modifies code via patches (unified diff format), it might inject dangerous code -- `eval()`, `exec()`, `chmod 777`, `disable_security`, or reverse shell setups. Even if individual guards catch these in shell commands or file writes, patches are a separate attack vector that needs its own analysis.

The PatchIntegrityGuard analyzes the diff to catch forbidden patterns in added lines and flags suspicious modification ratios (e.g., a patch that deletes 500 lines but adds only 2).

## How It Works

The guard parses the unified diff, counting added (`+`) and deleted (`-`) lines (skipping `+++`/`---` headers). It performs two checks:

1. **Forbidden patterns**: Checks added lines **only** against forbidden regex patterns -- deleted code doesn't matter because removing dangerous code is safe
2. **Imbalance ratio**: Computes `|additions - deletions| / max(additions, deletions)` and flags diffs exceeding the threshold, catching patches that are disproportionately destructive

## Configuration

```yaml
guards:
  patch_integrity:
    enabled: true
    max_imbalance_ratio: 0.9
    forbidden_patterns:
      - "eval\\s*\\("
      - "exec\\s*\\("
      - "chmod\\s+777"
      - "disable.*security"
```
