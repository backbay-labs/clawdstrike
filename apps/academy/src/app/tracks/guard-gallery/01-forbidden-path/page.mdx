# Forbidden Path Guard

## The Threat

AI agents with filesystem access can read SSH private keys, cloud credentials, environment files, Docker sockets, and other sensitive paths. Even "helpful" agents might access `~/.ssh/id_rsa` if asked to debug an SSH connection.

The ForbiddenPathGuard blocks access to a configurable set of glob patterns, ensuring agents never touch sensitive files regardless of how they justify the request.

## How It Works

The guard normalizes the requested path using **both** lexical normalization (resolving `..` segments textually) **and** filesystem-aware normalization (resolving symlinks). It then checks the path against a set of forbidden glob patterns using globset matching.

If **either** the lexical or resolved path matches a forbidden pattern, access is denied. This dual-check prevents symlink-based bypasses. The guard also supports an exceptions list -- paths that are allowed even if they match a forbidden pattern.

## Configuration

```yaml
guards:
  forbidden_path:
    enabled: true
    forbidden_patterns:
      - "**/.ssh/**"
      - "**/.aws/**"
      - "**/.env"
      - "**/etc/shadow"
      - "**/etc/passwd"
    exceptions:
      - "**/known_hosts"
```
