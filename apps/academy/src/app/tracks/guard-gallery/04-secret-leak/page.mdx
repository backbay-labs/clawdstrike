# Secret Leak Guard

## The Threat

AI agents that write files can accidentally (or deliberately via prompt injection) embed API keys, cloud credentials, private keys, and tokens in their output. Even writing a "helpful" configuration file might leak `OPENAI_API_KEY=sk-...` or embed an AWS secret access key.

The SecretLeakGuard scans file content for known secret patterns before the write reaches disk, catching leaks at the tool boundary.

## How It Works

The guard compiles a set of regex patterns at initialization. When a `file_write` or `patch` action occurs, it scans the content against all patterns. Each match has an assigned severity (`critical` for AWS keys, `warning` for generic secrets).

Key behaviors:
- The guard **blocks** if any match exceeds the configured severity threshold
- Matched values are **masked** in the evidence (showing only first/last characters)
- Credit card-like patterns run a **Luhn checksum** to reduce false positives
- Custom patterns can be added alongside the built-in set

## Configuration

```yaml
guards:
  secret_leak:
    enabled: true
    severity_threshold: warning  # block at warning or above
    custom_patterns:
      - name: "internal_token"
        pattern: "int-tok-[A-Za-z0-9]{32}"
        severity: critical
```
