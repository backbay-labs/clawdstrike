# Computer Use Guard

Computer Use Agents (CUA) interact with remote desktop sessions -- clicking, typing,
taking screenshots, transferring files. Without controls, a CUA could take any action
on a remote system.

## The Threat

A CUA with unrestricted access to a remote desktop session can:

- Navigate to malicious websites and download software
- Take screenshots to exfiltrate sensitive data displayed on screen
- Install unauthorized applications or backdoors
- Hijack active sessions by reconnecting or sharing access
- Execute arbitrary input sequences that mimic human actions

The risk is amplified because CUA actions happen through the same interface a human
would use -- there is no API boundary to enforce, only UI-level interactions.

## How It Works

The guard checks actions with `remote.*` or `input.*` type prefixes against an
allowlist of known action types. Three enforcement modes control behavior for
unknown actions:

1. **Observe** -- Always allow, just log (monitoring mode).
2. **Guardrail** -- Allow known actions. WARN (but allow) unknown ones.
3. **FailClosed** -- Allow known actions. DENY unknown ones.

10 default allowed actions include `remote.session.connect`, `remote.session.disconnect`,
`remote.session.reconnect`, `input.inject`, and various `remote.*` types.

## Configuration

```yaml
guards:
  computer_use:
    enabled: true
    mode: fail_closed  # observe | guardrail | fail_closed
    allowed_action_types:
      - "remote.session.connect"
      - "remote.session.disconnect"
      - "input.inject"
      - "remote.clipboard"
```

- **`mode`** -- Enforcement mode: `observe`, `guardrail`, or `fail_closed` (default: `fail_closed`)
- **`allowed_action_types`** -- List of allowed CUA action types
