# Egress Allowlist Guard

## The Threat

An AI agent making network requests can exfiltrate data to attacker-controlled servers, call unauthorized APIs, or connect to command-and-control infrastructure. The EgressAllowlistGuard ensures agents can only reach approved domains.

Even well-intentioned API calls can be dangerous -- an agent might decide to "helpfully" upload logs to an analytics endpoint, leaking sensitive data in the process.

## How It Works

The guard extracts the host from the network egress action and evaluates it against a domain policy. The domain policy supports:

- **Exact matches**: `api.openai.com`
- **Wildcard subdomains**: `*.example.com` (matches `sub.example.com` and `example.com`)
- **Configurable default action**: `allow` or `deny` (applied when no list matches)

The evaluation chain: check **blocked** domains first, then **allowed** domains, then fall back to the default action.

## Configuration

```yaml
guards:
  egress_allowlist:
    enabled: true
    allowed_domains:
      - "api.openai.com"
      - "api.anthropic.com"
      - "*.googleapis.com"
    blocked_domains:
      - "evil.com"
      - "*.malware.xyz"
    default_action: deny
```
