# Spider Sense Guard

Some threats don't match simple regex patterns or keyword lists. A sophisticated attacker
might use novel phrasing, euphemisms, or indirect references to describe malicious actions.
The SpiderSense guard uses embedding-based similarity matching to detect threats that are
semantically similar to known attack patterns, even if the exact words are different.

## The Threat

Traditional pattern-matching guards fail against semantic evasion:

```text
# Easily caught by keyword matching:
"Delete all database records"

# Not caught -- same intent, different words:
"Remove every entry from the persistent storage layer"
```

An attacker who knows which keywords a guard looks for can rephrase their instructions
to avoid detection while preserving the malicious intent. The SpiderSense guard solves
this by operating in embedding space -- where semantic meaning matters more than exact words.

## How It Works

Based on the Yu et al. 2026 hierarchical screening approach, the guard maintains a
`PatternDb` of threat pattern entries, each with a category, stage, and embedding vector.
When screening input text:

1. **Compute embedding** -- The input text is converted to a vector representation.
2. **Cosine similarity search** -- The guard calculates cosine similarity against all
   patterns in the database.
3. **Threshold check** -- If the top similarity score exceeds the `similarity_threshold`
   (default: 0.85), the verdict is **Deny**.
4. **Ambiguity band** -- If the score falls in the ambiguity band (between threshold and
   a lower bound), the verdict is **Escalate** for further review.
5. **Allow** -- Otherwise, the input is allowed.

The built-in pattern database (`s2bench-v1.json`) contains 36 entries organized by the
S2Bench taxonomy: 4 attack stages x 9 attack types, with 3-dimensional demo embeddings.

Optionally, an LLM "deep path" can be enabled for cases in the ambiguity band -- the
LLM evaluates whether the flagged text truly represents a threat.

## Configuration

```yaml
guards:
  spider_sense:
    enabled: true
    pattern_db_path: "builtin:s2bench-v1"
    similarity_threshold: 0.85
    ambiguity_band: 0.15
    deep_path_enabled: false  # Optional LLM deep path
```

- **`pattern_db_path`** -- Path to pattern database (use `builtin:s2bench-v1` for the built-in DB)
- **`similarity_threshold`** -- Cosine similarity score above which to deny (default: 0.85)
- **`ambiguity_band`** -- Width of the escalation zone below the threshold (default: 0.15)
- **`deep_path_enabled`** -- Enable optional LLM deep reasoning for ambiguous cases (default: false)
