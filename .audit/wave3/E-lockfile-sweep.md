### Headline problems

1. **Three-way package-manager schizophrenia at root.** Root declares `npm` workspaces in `package.json`, but ships both `package-lock.json` AND `bun.lockb`. Neither is consumed by CI. Pick one (or delete both).
2. **15 redundant `package-lock.json` files** inside members of the npm workspace. Workspace members must not carry their own lockfile — but CI bootstraps each one with `npm ci` because the repo uses `file:` deps + per-package install instead of true workspace hoisting. Either commit to workspaces (delete child locks) or delete the workspace declaration (keep child locks).
3. **`apps/workbench` carries *both* `bun.lock` and `package-lock.json`.** CI uses `npm ci`; the `bun.lock` is dead.
4. **`apps/agent/src-tauri/Cargo.lock` is uncommitted to mise/CI invariants.** `mise.toml` runs `cargo check --manifest-path apps/agent/src-tauri/Cargo.toml` but the lockfile next to it is currently **modified** (per `git status`) without `cargo deny` covering it the way `apps/desktop/src-tauri` is. Same story for `apps/workbench/src-tauri`.
5. **No root Python lockfile.** `uv.lock` exists only inside `packages/sdk/hush-py/`. Three other Python projects (`hush-native`, `hello-secure-agent-py`, `spine-reticulum-adapter`) have no lock at all.

## Per-Ecosystem Analysis

### npm / bun

**Canonical lockfile situation:** There isn't one. CI bypasses the root entirely and runs `npm --prefix <member>/ ci` against each member's own `package-lock.json`. Locally, `bun install` at root produces `bun.lockb`; `npm install` at root produces `package-lock.json`; neither is consumed by CI. The "workspaces" array in root `package.json` is decorative.

**Two viable resolutions (pick one):**

**Strategy A — Commit to npm workspaces (delete child locks).**
- Keep root `package-lock.json`, delete root `bun.lockb`.
- Delete all 14 `package-lock.json` files in workspace members.
- Rewrite CI to run `npm ci` once at root and rely on hoisting.
- Resolve the `file:` deps (e.g. `"@clawdstrike/sdk": "file:../../packages/sdk/hush-ts"` in examples) — these are *fine* in non-workspace examples but redundant inside workspaces, where `workspace:*` or just the name should be used.
- Risk: `smoke-ts-file-deps.sh` exists precisely to verify the file-dep flow works for non-workspace consumers. That flow must be preserved.

**Strategy B — Abandon root workspaces (delete root locks).**
- Delete root `package.json`'s `workspaces` array (or delete root `package.json` entirely if biome can be moved).
- Delete root `package-lock.json` and root `bun.lockb`.
- Keep every per-package `package-lock.json` (already what CI does).
- Add a CI guard: `find . -maxdepth 2 -name 'package-lock.json' | xargs -I {} dirname {} | xargs -I {} sh -c 'cd {} && npm ci'`.

**Recommendation: Strategy B.** The codebase's actual workflow (file:-dep examples + per-member npm ci) is consistent with no-workspaces. The current "workspaces" field misleads contributors into running `npm install` at root, which generates a giant lockfile nobody uses. Biome can be moved to a separate config file or installed via mise.

**Redundancies regardless of strategy:**
- `apps/workbench/bun.lock` — DELETE (CI uses `npm ci` in this dir).
- Root `bun.lockb` — DELETE (no CI consumer; root is configured as an npm workspace, not a bun workspace).

**Verify-before-delete:**
- `cursor-plugin/bun.lockb` and `clawdstrike-plugin/bun.lockb` are **byte-identical in size** (both 37,300). Likely one was copy-pasted from the other when cursor-plugin was forked. Re-resolve both with `bun install` and re-commit.
- The four `examples/*/package-lock.json` files at exactly 17,866 / 17,747 bytes suggest stale shared snapshots. Re-resolve each.

### Python (uv / pip / poetry)

**Current state:**
- 4 `pyproject.toml` files, 1 `uv.lock`, 0 root manifest, 0 root lock.
- No `poetry.lock`, no `Pipfile.lock`, no `requirements.txt`. Clean — one tool.

**hush-py duplication:**
- `packages/sdk/hush-py/pyproject.toml` declares `name = "clawdstrike"`, `version = "0.2.7"`, builds with **hatchling**.
- `packages/sdk/hush-py/hush-native/pyproject.toml` declares `name = "clawdstrike"`, `version = "0.2.7"`, builds with **maturin**.
- Two packages with the same name and version, different build backends, in nested directories. **This is a publish hazard.** PyPI will reject the second one or silently overwrite. Recommendation: rename the maturin package to `clawdstrike-native` (matches its `module-name = "clawdstrike._native"`), or merge into a single hatchling+maturin hybrid.

**Missing `uv.lock` for reticulum adapter:**
`integrations/transports/reticulum/pyproject.toml` is a deployable package (`spine-reticulum-adapter`) with 8 runtime deps including `rns`, `lxmf`, `nats-py`. No `uv.lock` means non-reproducible installs. Add `uv.lock` here.

**Missing `uv.lock` for hello-secure-agent-py:** Acceptable — examples often omit locks intentionally. Leave it.

**Out-of-sync check (`uv.lock` vs `pyproject.toml`):** Could not run `uv lock --check` from this audit. Recommend running `uv lock --check --project packages/sdk/hush-py` as a CI gate.

**No root Python workspace:** The codebase has 4 Python projects but no umbrella `pyproject.toml` with `[tool.uv.workspace]`. Adding one would let `uv lock` resolve them coherently and avoid drift in shared deps (e.g. all four depend on `pyyaml`, three depend on `pynacl`/`PyNaCl` — note the casing mismatch between `pynacl` in hush-py and `PyNaCl` in reticulum, which uv normalizes but pip does not on some platforms).
