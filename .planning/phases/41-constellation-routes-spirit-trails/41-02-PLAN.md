**File 1: SpiritTrailsLayer.tsx**

Create `apps/workbench/src/features/observatory/components/world-canvas/SpiritTrailsLayer.tsx`.

**Props interface:**
```typescript
import type { SpiritMood } from "@/features/spirit/types";

interface SpiritTrailsLayerProps {
  spiritAccentColor: string;  // hex, e.g. "#d4a84b"
  spiritMood: SpiritMood;     // "idle" | "active" | "alert" | "dormant"
  spiritLevel: number;        // 1-5
  playerPosition: [number, number, number]; // current player XZ position (Y from flight state)
}
```

**Implementation:**

1. Module-level constants:
   - `MAX_TRAIL_POINTS = 150` (per SPRT-05 locked requirement)
   - `TRAIL_SAMPLE_DISTANCE = 8` — minimum distance between trail points (world units) to avoid clumping
   - `FADE_START_FRACTION = 0.75` — oldest 25% of points start fading (per CONTEXT.md: "60% opacity fadeout on oldest quarter")

2. Use a `useRef` to store an array of `THREE.Vector3` points (the trail buffer). On each frame (`useFrame`):
   - If `playerPosition` has moved more than `TRAIL_SAMPLE_DISTANCE` from the last recorded point, push a new `new THREE.Vector3(playerPosition[0], 2, playerPosition[2])` (Y=2, slightly above ground plane).
   - If buffer length exceeds `MAX_TRAIL_POINTS`, shift the oldest point off.
   - Update a version counter ref to trigger re-render.

3. Mood-driven visual parameters (per SPRT-02):
   ```typescript
   const MOOD_CONFIG: Record<SpiritMood, { opacityBase: number; widthBase: number; pulse: boolean }> = {
     idle:    { opacityBase: 0.25, widthBase: 0.8,  pulse: false },
     active:  { opacityBase: 0.55, widthBase: 1.2,  pulse: false },
     alert:   { opacityBase: 0.7,  widthBase: 1.5,  pulse: true },
     dormant: { opacityBase: 0.1,  widthBase: 0.5,  pulse: false },
   };
   ```

4. Level-driven intensity scaling (per SPRT-03):
   ```typescript
   // Level 1 = 0.3 multiplier (faint wisps), Level 5 = 1.0 (vivid luminous ribbons)
   const levelMultiplier = 0.3 + (spiritLevel - 1) * 0.175;
   ```

5. Render as a drei `<Line>` component (not `<Trail>` — `<Trail>` wraps a child mesh and follows it; we need a static polyline of accumulated positions):
   - `points` = the trail buffer array
   - `color` = `new THREE.Color(spiritAccentColor)`
   - `lineWidth` = `moodConfig.widthBase * levelMultiplier`
   - `transparent={true}`
   - `opacity` = `moodConfig.opacityBase * levelMultiplier`
   - `depthWrite={false}`
   - `toneMapped={false}`

6. For the alert pulse effect (SPRT-02): use `useFrame` to oscillate opacity between `opacityBase * 0.6` and `opacityBase * 1.0` using `Math.sin(clock.elapsedTime * 4) * 0.5 + 0.5`. Only when `spiritMood === "alert"`.

7. For per-vertex fade of oldest quarter (SPRT-05): drei `<Line>` supports `vertexColors`. Build a `Float32Array` of RGBA for each point where the oldest 25% fade from 0 opacity to full. Use `<Line vertexColors={vertexColors} ...>`.

   Actually, drei Line does not directly support per-vertex alpha fading. Instead, use the `<Line>` `color` prop and accept that uniform opacity is the best approach. Add a second `<Line>` with the newest 75% of points at full opacity, and a third covering the oldest 25% at reduced opacity. Or more simply: render the trail as a single Line and accept uniform fade. Per CONTEXT.md the requirement says "oldest points fading out" — implement by splitting the trail buffer into two segments in the render:
   - Segment 1 (oldest quarter): `trailPoints.slice(0, fadeEndIndex)` with `opacity * 0.35`
   - Segment 2 (newest 75%): `trailPoints.slice(Math.max(0, fadeEndIndex - 1))` with full `opacity`
   Both use the same color and lineWidth. The 1-point overlap ensures visual continuity.

8. Wrap in `<group name="spirit-trails">`. Only render if trail has >= 2 points.

9. Export `SpiritTrailsLayer` as named export.
