    **useDockingSystem.ts:**
    Create new file. This is a useFrame-driven hook that manages the full docking lifecycle.

    Props interface:
    ```typescript
    export interface UseDockingSystemOptions {
      shipRef: React.RefObject<THREE.Group | null>;
      intentRef: React.RefObject<FlightIntent>;
      /** Ref to external velocity vector in useFlightLoop — used for magnet-pull bias */
      velocityRef: React.RefObject<THREE.Vector3>;
      /** Callback to disable/enable flight input processing */
      setFlightInputEnabled: (enabled: boolean) => void;
      /** Callback to push docking state to store (~100ms throttle) */
      onDockingStateChange?: (state: DockingState) => void;
    }
    ```

    Module-level scratch objects (zero-alloc hot path):
    ```typescript
    const _dockPoint = new THREE.Vector3();
    const _shipToDock = new THREE.Vector3();
    const _pushDir = new THREE.Vector3();
    const _stationPos = new THREE.Vector3();
    ```

    Internal refs:
    - `dockingRef` — current DockingState (ref, not state)
    - `dockLockProgressRef` — 0 to 1 lerp progress during dock lock
    - `dockLockStartPosRef` — ship position when dock lock triggered (THREE.Vector3)
    - `undockGraceStartMsRef` — timestamp of undock for grace period
    - `flightInputEnabledRef` — tracks whether flight was disabled by docking

    **useFrame logic (every frame):**

    1. **If undock grace period active:** Check elapsed time. If `now - undockGraceStartMs >= 500ms`, clear grace flag, set zone to null.

    2. **If zone === "dock" (docked):**
       - Check `intent.interactTriggered` for undock (E key).
       - If undock triggered:
         a. Compute push direction: normalize(ship.position - station.position).
         b. Set velocity to pushDir * DOCKING_CONFIG.undockPushVelocity.
         c. Move ship pushDir * 2 units immediately (small initial separation).
         d. Re-enable flight input via `setFlightInputEnabled(true)`.
         e. Set zone to null, stationId to null, undockGracePeriodActive to true, record undockGraceStartMs.
       - Otherwise: hold ship at dock point (prevent drift).

    3. **If dockLockStartMs !== null (dock lock sequence in progress):**
       - Compute progress: `(now - dockLockStartMs) / DOCKING_CONFIG.dockLockDurationMs`.
       - If progress < 1: lerp ship.position from dockLockStartPos to dockPoint. Use easeOutCubic: `t = 1 - (1 - p) ** 3`.
       - If progress >= 1: snap to dockPoint, set zone to "dock", clear dockLockStartMs.
       - Zero the velocity ref (ship should be stationary during lock).

    4. **If not docked and not in dock lock:**
       - Compute distances from ship to all stations (reuse OBSERVATORY_STATION_POSITIONS + HUNT_STATION_ORDER).
       - Find nearest station within approachRadius.
       - If none: set zone to null, stationId to null.
       - If in magnet range (15-50 units):
         a. Set zone to "magnet", stationId.
         b. Compute dock point: station position (use station center for now — dock point offset is Claude's discretion, use station.y + 0 offset).
         c. Compute pull direction: normalize(dockPoint - ship.position).
         d. Compute pull strength: `THREE.MathUtils.mapLinear(dist, 50, 15, 0, 0.3)` — stronger as closer.
         e. Add velocity bias: `velocityRef.current.addScaledVector(pullDirection, pullStrength * 60 * dt)` — the `* 60 * dt` normalizes across frame rates.
         f. Ship can still thrust away — this is additive, not overriding.
       - If in dock lock range (<15 units) AND speed < 12 AND not in undock grace:
         a. Set zone to "dock" sequence start.
         b. Record dockLockStartMs = now, dockLockStartPosRef = ship.position.clone().
         c. Disable flight input via `setFlightInputEnabled(false)`.
       - If in approach range (50-180): set zone to "approach", stationId.

    5. **Throttled store update:** Every 100ms, push dockingState to store via onDockingStateChange callback (same pattern as useFlightLoop snapshot throttle).

    **useFlightLoop.ts modifications:**
    1. Export `velRef` so useDockingSystem can access the velocity vector. Change `const velRef = useRef(...)` to be returned from the hook: `return { velRef }`.
    2. Update UseFlightLoopOptions to optionally accept `flightInputEnabled: React.RefObject<boolean>` — when false, skip thrust/rotation processing (ship coasts to stop via damping, or docking system takes over). Default ref value: true.
    3. In the useFrame body, after reading intent, add: `if (flightInputEnabledRef?.current === false) { /* zero thrust/rotation, still apply damping and position update */ }`. Specifically: skip the rotation block and thrust block, but keep damping and position update so the ship decelerates smoothly.

    **SpaceFlightController.tsx modifications:**

    2. Import `useObservatoryStore` from store.
    3. Create `flightInputEnabledRef = useRef(true)` and `setFlightInputEnabled` callback that sets the ref.
    4. Destructure `{ velRef }` from useFlightLoop (now returns it).
    5. Pass `flightInputEnabled` ref to useFlightLoop options.
    6. Call `useDockingSystem({ shipRef, intentRef, velocityRef: velRef, setFlightInputEnabled, onDockingStateChange })`.
    7. `onDockingStateChange` callback calls `useObservatoryStore.getState().actions.setDockingState(state)`.
    8. Update handleStateChange to NOT overwrite playerFocusRef when docked (the docking system manages position during dock lock).
