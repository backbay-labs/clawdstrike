    interface StationArrivalCardProps {
      stationId: HuntStationId | null;
      visible: boolean;
      onComplete: () => void;
    }

    Sequence when visible=true and stationId is non-null:
    1. Letterbox bars slide in from top/bottom (0.3s, CSS transform translateY) — bars are 40px high, bg black, absolute positioned.
    2. Station name fades in at center (0.3s delay, opacity 0->1). Styled: uppercase, station color from STATION_COLORS_HEX[stationId], font-size 32px, font-mono, tracking-widest.

    4. Hold for 1.2s.
    5. Fade out name (0.3s).
    6. Letterbox bars retract (0.3s).
    7. Call onComplete().

    Total duration: 0.3 + 0.3 + 1.2 + 0.3 + 0.3 = 2.4s.

    **Proximity detail fade (TRN-05):**

    The existing LOD system uses drei Detailed with distances=[0,60,180,500] for 4-tier station detail. This already handles most visibility switching. The task is to add smooth opacity fading for specific sub-elements rather than hard LOD pops.

    **Add a `useStationProximityFade` hook or inline logic:**
    - In the station rendering section of ObservatoryWorldCanvas, compute per-station distance from the ship.
    - Read ship position from observatory store: `useObservatoryStore.getState().flightState.position` in a useFrame callback (not subscription).
    - For each station, compute distance and derive opacity for sub-elements:
      - NPC crew: visible (opacity 1.0) below 120 units, fade from 0.0 to 1.0 between 120-180 units, invisible (opacity 0.0) above 180 units. Formula: `clamp((180 - distance) / 60, 0, 1)`.
      - Artifact count badge (if rendered in 3D): visible below 120 units, fade between 80-120 units.
      - Distance marker / station label: fade OUT as approaching — opacity goes from 1.0 at 180 units to 0.0 at 60 units. Formula: `clamp((distance - 60) / 120, 0, 1)`.
    - Since distance changes continuously, use a ref-based approach:
      - Create a module-level `stationDistancesRef` that stores current distances per station.
      - Update in a single useFrame callback that iterates all 6 stations.
      - Sub-components read from this ref.

    **Implementation approach — minimal touch:**
    The existing drie Detailed component handles LOD hard-cuts. For smooth fading, the simplest approach is to pass a `proximityOpacity` prop to StationNpcCrew and any other sub-element components.

    If StationNpcCrew doesn't accept opacity, wrap its group in a `<group>` with `visible={distance < 180}` — this is already approximately handled by LOD. For smoother fading, apply material opacity to NPC instances.

    **Pragmatic minimum:**
    Given that the existing LOD system (Detailed distances=[0,60,180,500]) already switches between full/simplified/billboard/beacon tiers, and this is quite similar to TRN-05's fade distances, the main additions are:
    1. NPC crew opacity fade between 120-180 units (the LOD shows full mesh at <60 but NPCs should be visible slightly farther).
    2. Artifact badge opacity fade-in between 80-120 units.

    Add a `stationProximityRef` at module level (Record<HuntStationId, number>) updated once per frame. Components that need proximity data read from it.

    For NPC crew: if StationNpcCrew mounts inside the Detailed tier that is only visible at <60 units, the NPC fade between 120-180 is moot because they are already hidden by LOD. In that case, check if NPCs should be moved to a wider LOD tier or if the Detailed distances should be adjusted. If NPCs are already in the near LOD tier (<60), adjust the Detailed distance for that tier from 60 to 180 and add opacity fade within the tier.

    If this would require deep surgery to the Detailed component, a simpler approach: add a separate `<group visible={distance < 180}>` wrapping NPCs outside the Detailed component, with opacity controlled by distance.
