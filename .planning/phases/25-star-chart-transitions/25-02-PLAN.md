  <action>
    **flight-types.ts — Add autopilot field to FlightState:**
    - Add `autopilotTargetStationId: HuntStationId | null` to FlightState interface.
    - Set to `null` in DEFAULT_FLIGHT_STATE.

    **observatory-store.ts — Add autopilot actions:**
    - Add `autopilotTargetStationId: HuntStationId | null` as a top-level store field (default null). Keep it separate from flightState since it is a user intent, not physics state.
    - Add actions:
      - `setAutopilotTarget: (stationId: HuntStationId | null) => void` — sets autopilotTargetStationId.
      - `clearAutopilot: () => void` — sets autopilotTargetStationId to null.

    **useFlightLoop.ts — Add autopilot quaternion slerp + thrust:**
    - Add a module-level `_targetPos = new THREE.Vector3()` and `_toTarget = new THREE.Vector3()` and `_targetQuat = new THREE.Quaternion()` for scratch allocations.
    - Add `autopilotTargetStationId` to UseFlightLoopOptions as an optional `React.RefObject<HuntStationId | null>`. The caller will pass a ref that reads from the store.
    - In the useFrame callback, AFTER the existing inputActive check but BEFORE the damping section:
      1. Read autopilotTargetStationId from the ref.
      2. If non-null AND inputActive:
         a. Look up target position from OBSERVATORY_STATION_POSITIONS.
         b. Compute direction from ship to target: `_toTarget.copy(_targetPos).sub(ship.position).normalize()`.
         c. Build target quaternion: `_targetQuat.setFromUnitVectors(new THREE.Vector3(0, 0, -1), _toTarget)` — BUT use a pre-allocated scratch vector, not `new`. Actually better: use `_forward.set(0,0,-1)` then `_targetQuat.setFromUnitVectors(_forward, _toTarget)`.
         d. Slerp ship quaternion toward target: `ship.quaternion.slerp(_targetQuat, 0.03)` per CONTEXT.md.
         e. Check alignment: `_forward.set(0,0,-1).applyQuaternion(ship.quaternion); const dot = _forward.dot(_toTarget);`
         f. If dot > 0.95, apply cruise thrust along ship forward (same as intent.thrust=1 logic).
         g. If distance to target < dockProximityRadius (50), the existing dock zone logic will take over — autopilot should be cleared. Dispatch a custom event 'observatory:autopilot-cancel' or directly call a callback.
      3. If any WASD/mouse intent is non-zero (thrust !== 0 || strafe !== 0 || vertical !== 0 || mouseDeltaX !== 0 || mouseDeltaY !== 0), cancel autopilot by calling an onAutopilotCancel callback.
    - Add `onAutopilotCancel?: () => void` to UseFlightLoopOptions.
    - In the store snapshot section, include `autopilotTargetStationId` from the ref in the FlightState snapshot so HUD/chart can read it.

    **Important:** The autopilot slerp happens INSTEAD of mouse rotation when autopilot is active, not in addition to it. Check `autopilotRef.current !== null` — if true, skip mouse rotation but still apply autopilot rotation.
  </action>
